1. Executive Summary & The Impending Quantum Horizon

1.1 ภัยคุกคามคอมพิวเตอร์ควอนตัม (Cryptanalytically Relevant Quantum Computer - CRQC)

ในปัจจุบัน โครงสร้างพื้นฐานความมั่นคงปลอดภัยไซเบอร์ของภาคการเงิน ธนาคาร โทรคมนาคม และหน่วยงานรัฐบาลทั่วโลก พึ่งพาวิทยาการรหัสลับแบบกุญแจอสมมาตร (Asymmetric Public-Key Cryptography) เป็นหลัก ได้แก่ RSA (2048 - 4096 บิต), ECDSA (secp256k1, P-256), และ Diffie-Hellman / ECDH

เมื่อคอมพิวเตอร์ควอนตัมที่มีความเสถียร (Fault-Tolerant Quantum Computer) บรรลุขีดความสามารถประมาณ $4,000 - 10,000$ Logical Qubits (คาดการณ์ช่วงปี 2029 – 2030 หรือเรียกว่า Q-Day): 1. Shor's Algorithm (1994): สามารถแยกตัวประกอบจำนวนเต็ม (Integer Factorization) และคำนวณ Discrete Logarithm ได้ในเวลาเชิงพหุนาม (Polynomial Time $O((\log N)^3)$) — ทำลายระบบ RSA และ ECC ทั้งหมดทันที 2. Grover's Algorithm (1996): ลดระดับความปลอดภัยของอัลกอริทึมกุญแจสมมาตรและฟังก์ชันแฮชลงครึ่งหนึ่ง ($O(\sqrt{N})$) — ทำให้ AES-128 มีความแข็งแกร่งเหลือเพียง 64 บิต ในขณะที่ AES-256 / ChaCha20 ยังคงปลอดภัยที่ 128 บิต

1.2 วิกฤตด่วนปัจจุบัน: "Harvest Now, Decrypt Later" (HNDL)

องค์กรส่วนใหญ่เข้าใจผิดว่าภัยควอนตัมเป็นเรื่องของอนาคต แต่ในความเป็นจริง การโจมตีได้เริ่มต้นขึ้นแล้วในวันนี้: - กลุ่มผู้โจมตีระดับรัฐ (Nation-State Threat Actors) กำลังดักจับและกักตักเก็บข้อมูลทราฟฟิกเครือข่ายที่เข้ารหัส (Encrypted Intercepts) ทางทะเล เคเบิลใต้น้ำ ดาต้าเซ็นเตอร์ และคลาวด์ - ข้อมูลที่ถูกเก็บไว้ (เช่น ข้อมูลประวัติธุรกรรมธนาคาร, ความลับทางการค้า, ข้อมูลพันธุกรรม, และความลับความมั่นคงของชาติ) จะถูกนำมาถอดรหัสย้อนหลังทันทีที่เครื่องควอนตัมพร้อมใช้งาน - บทสรุป: หากไม่เปลี่ยนผ่านสู่ระบบ Post-Quantum ในวันนี้ ข้อมูลทราฟฟิกทั้งหมดที่ส่งผ่านอินเทอร์เน็ตในปัจจุบันถือว่าตกอยู่ในความเสี่ยงแล้ว 100%

5. Constant-Time & Timing Attack Vulnerability Analysis (DudeCT)

ความท้าทายสำคัญที่สุดของอัลกอริทึมแลตทิซ (ML-KEM และ ML-DSA) คือความเสี่ยงต่อการถูกเจาะระบบผ่าน Side-Channel Timing Attacks (การดักวัดเวลาการประมวลผลในระดับนาโนวินาทีเพื่อเดาคีย์ลับ)

TUMQuantum ได้พัฒนาชุดทดสอบ Constant-Time & Timing Attack Analyzer ตามระเบียบวิธีวิจัย DudeCT (Welch's Two-Sample t-test) เพื่อพิสูจน์ว่าไม่มีการรั่วไหลของเวลา:

5.1 ระเบียบวิธีทางสถิติ (DudeCT Methodology)

  1. การจำแนกอินพุต 2 กลุ่ม (Two Input Classes):
  2. Class 0 (Baseline / Constant): อินพุตที่มีคีย์/Ciphertext/Signature คงที่
  3. Class 1 (Random / Variance): อินพุตสุ่มหรือถูกดัดแปลงในตำแหน่งต่างๆ
  4. การวัดเวลาความละเอียดสูงและการสลับลำดับแบบสุ่ม (Interleaved Execution):
  5. ทำการวัดเวลาแบบสลับกัน (Interleaved) เพื่อตัดปัจจัยสัญญาณรบกวน เช่น อุณหภูมิ CPU (Thermal Throttling) หรือการจัดคิวของ OS Scheduler
  6. ใช้ Hardware Timestamp Counter ความละเอียดระดับ Sub-Nanosecond
  7. การตัดค่าผิดปกติ (Percentile Outlier Trimming):
  8. ตัดข้อมูลร้อยละ 1 บนสุด (Top 1% Percentile) ที่เกิดจาก OS Interrupts หรือ Thread Preemption
  9. การทดสอบสมมติฐานทางสถิติ (Welch's t-statistic): $$t = \frac{\bar{X}_0 - \bar{X}_1}{\sqrt{\frac{S_0^2}{N_0} + \frac{S_1^2}{N_1}}}$$
  10. เกณฑ์การตัดสิน (Threshold):
    • หาก $|t| < 4.5$ : ยอมรับสมมติฐานว่าไม่มีความแตกต่างของการกระจายเวลา ($p > 10^{-5}$) $\rightarrow$ PASS (Constant-Time Certified)
    • หาก $|t| \ge 4.5$ : มีความแตกต่างทางเวลาที่สัมพันธ์กับข้อมูลลับอย่างมีนัยสำคัญ $\rightarrow$ FAIL (Timing Leakage Detected)

5.2 มาตรการป้องกันการรั่วไหลในระดับ Microarchitecture

  1. Branchless Arithmetic Sign Shift:
  2. การตรวจสอบขอบเขตสัมประสิทธิ์พหุนามแลตทิซ ต้องไม่ใช้คำสั่ง Jump หรือเงื่อนไข if (x > threshold) เพราะ Branch Predictor ใน CPU จะทำให้เกิดความแตกต่างของเวลาที่วัดได้ ($|t| > 100$)
  3. ใช้การเลื่อนบิตเครื่องหมาย (Sign Shift Arithmetic) แทนคำสั่งกระโดด: csharp int diff = threshold - coefficient; byte boundMask = (byte)(diff >> 31); violations += ConstantTimeSelect(boundMask, 1, 0);
  4. Fixed-Time Array Comparisons:
  5. ใช้ CryptographicOperations.FixedTimeEquals() ตรวจสอบค่าแฮชและ Authentication Tags โดยไม่มีการ Early-Exit
  6. Memory Zeroization:
  7. ล้างค่ากุญแจลับในหน่วยความจำทันทีหลังใช้งานด้วย CryptographicOperations.ZeroMemory()

  7. สำนักงานพัฒนาธุรกรรมทางอิเล็กทรอนิกส์ (สพธอ. / ETDA):
  8. รองรับ พ.ร.บ.ว่าด้วยธุรกรรมทางอิเล็กทรอนิกส์ พ.ศ. 2544 (และฉบับแก้ไขเพิ่มเติม) ผ่านการใช้งาน RFC 3161 Post-Quantum Time-Stamp Authority (PQC-TSA) เพื่อการรับรองเอกสารอิเล็กทรอนิกส์ที่มีผลผูกพันทางกฎหมายยาวนานกว่า 10 ปี

8. คู่มือเริ่มต้นใช้งานด่วน (Quick Start Guide)

  • พอร์ต 443 (HTTPS): ให้บริการ Post-Quantum TLS 1.3 พร้อม Key Encapsulation X25519MLKEM768
  • พอร์ต 5100: Sovereign PQC Cryptography REST API
  • พอร์ต 8080: Upstream Legacy Web Server แสดงหน้าผลลัพธ์พร้อม Injected PQC Headers
